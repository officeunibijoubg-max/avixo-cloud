# avixo-cloud

Всяка сутрин в 7:00 (Европа/София) прави **12 рекламни визуала 1080×1080** за
следващия продукт от каталога на avixo.eu и ги качва в Google Drive, в нова
подпапка с датата.

Върви на GitHub Actions — не зависи от твоя компютър.

```
07:00 → чете каталога → избира днешния продукт → сваля снимката
      → рендерира 12 варианта с Chrome → качва в Drive/ad-formats/ГГГГ-ММ-ДД_<продукт>/
```

## Еднократна настройка

### 1 · OAuth достъп до Google Drive

**Не използвай service account.** Той няма собствена дискова квота — при качване
Google отказва с „Service Accounts do not have storage quota". Заобикалянията
(Shared Drive, domain-wide delegation) искат Google Workspace. С OAuth файловете
се качват от името на потребителя, в неговата квота.

1. [Google Cloud Console](https://console.cloud.google.com/) → проекта
2. **APIs & Services → Library** → включи **Google Drive API**
3. **APIs & Services → OAuth consent screen** → User type **External** →
   попълни име и имейл → добави scope (нужен е само `https://www.googleapis.com/auth/drive.file`
4. **Publishing status → Publish app** (In production). Ако остане в *Testing*,
   refresh token-ът изтича след **7 дни** и пускът спира да работи.
5. **Credentials → Create credentials → OAuth client ID** → тип **Desktop app**
6. Издай refresh token еднократно (виж `docs/oauth.md`)
### 2 · Секрети в GitHub

Repo → *Settings* → *Secrets and variables* → *Actions* → *New repository secret*:

| Име | Стойност |
|---|---|
| `GOOGLE_OAUTH_CLIENT_ID` | от OAuth клиента |
| `GOOGLE_OAUTH_CLIENT_SECRET` | от OAuth клиента |
| `GOOGLE_OAUTH_REFRESH_TOKEN` | издаденият token |
| `DRIVE_PARENT_FOLDER_ID` | `1oc7Uif00huv56USnxcdCMvzyIYUP_H0A` |

ID-то на папката е частта след `/folders/` в нейния URL.

### 3 · Пробен пуск

Repo → *Actions* → **Дневни визуали** → *Run workflow*. Ръчният пуск не чака 7:00.

## Ротацията

Продуктът за деня се избира **без състояние**: индексът е броят дни от епохата
по модул броя продукти. Няма файл с брояч, който да се разсинхронизира, и
повторно пускане в същия ден дава същия продукт.

Каталогът е подреден по референтен номер, не по реда във витрината — иначе
пренареждане на сайта би върнало вчерашния продукт.

## За часа

Cron е винаги в UTC, а България мени часа два пъти годишно. Затова workflow-ът
има **два** cron реда (04:00 и 05:00 UTC) и проверка вътре в job-а, която пуска
само този, при който в София наистина е 7 часа. Единичен ред би се разминавал с
час половин година.

## Локален тест

```bash
npm ci
npm run test:local                      # 3 варианта, без качване
node src/daily.mjs --url https://avixo.eu/... --count 12 --no-upload
```

Изходът отива в `.work/out/`.

## Правила за куките

Пълните правила са в skill-а `avixo-visuals` (`references/hooks-bg.md`). Накратко:

- **Куката е в първите думи.** Човек вижда две думи, преди да реши да скролне.
- 2–4 думи, главни букви, число или глагол напред.
- Без удивителни, без „СПЕЦИАЛНА ОФЕРТА", „ПРОМОЦИЯ", „НЕ ПРОПУСКАЙ".
- Обръщение на „ти".
- Ръкописният ред е **емоция**, не оферта.
- Контрастът продукт↔фон решава палитрата: тъмен продукт → светла палитра.

Пиши само неща, които стоят на продуктовата страница. Не назовавай чужди марки —
рекламните платформи отхвърлят такива креативи.

## Известни ограничения

- **Каталогът чете само първата страница** на всяка категория. Ако сайтът има
  пагинация, ротацията обхваща само видимите продукти (~16 на категория). Стига
  за месец различни визуали, но не покрива целия каталог.
- **Кодът не е изпълняван локално.** Написан е без достъпен Node на машината,
  където е създаден. Първият истински тест е ръчният пуск от *Actions*.
- Изрязването на фона се чупи при **бял или сребрист продукт на бял фон** —
  алгоритъмът различава продукт от фон по това, че продуктът е по-тъмен.
